# 大声说话 · Loud Speak

Windows 局域网匿名公共聊天室。Node.js 22 LTS；SQLite 本地保存，无外部账号或云服务依赖。

## 安装

```powershell
git clone https://github.com/386349036/Loud_Speak.git
cd Loud_Speak
npm ci --cache .npm-cache
```

需要预先安装 Node.js 22 LTS 或更高版本。

## 启动

双击 `start.cmd`，保持窗口打开。首次打开 **http://localhost:3210/admin**，点击绑定 Google Authenticator，在手机中扫码并输入动态码确认；随后保存一次性恢复码。同事访问 **http://你的内网IP:3210**，以启动窗口显示的当前内网地址为准。电脑睡眠、关机或关闭服务会中断访问。

如果内网访问失败，在管理员 PowerShell 中执行 `powershell -ExecutionPolicy Bypass -File .\allow-lan.ps1`。规则仅放行专用网络、本地子网 TCP 3210。公司网络若为公用配置或跨 VLAN，请由网管确认规则，不要关闭防火墙。未配置公网映射。

建议由路由器 DHCP 静态地址分配绑定本机网卡到固定内网 IP，先确认地址与 DHCP 池无冲突。DNS 无需调整。可使用环境变量 PORT 和 HOST 改端口/监听地址，防火墙规则需同步修改。

## 使用与管理

- 每次加载页面生成新的匿名身份与随机昵称，刷新、关闭后重开、恢复标签页均重新分配；身份凭证只保存在页面内存中。无需实名，不承诺网络层面不可追踪；应用不记录消息发送者 IP。
- 文字上限 4000 字符，附件最大 20 MB，PNG/JPEG/GIF/WebP 可预览，其他文件下载。每个来源地址每分钟最多 30 次发送，首次分配身份每分钟最多 60 次；共享出口可能共用限额。
- 用户默认看近 6 小时；服务器默认保存 720 小时（30 天）。管理员在后台分别修改整数小时，服务器保存设为 0 表示永久；有限保存时长不能短于可见时长。
- 后台支持搜索昵称/正文、起止时间、分页、附件下载和永久删除。缩短保留时间触发数据删除时需确认数量和大小。
- 后台“一键清空前端记录”让当前全部消息立即对普通用户过期，在线页面同步清空，旧附件也无法由普通用户继续下载；后台历史和附件仍按服务器保存时长保留。新消息正常显示，重启服务或调长可见时长不会恢复已清空的旧消息。已下载的内容无法撤回。首次升级后聊天页面需刷新一次加载新逻辑。
- 后台“关闭聊天 / 开启聊天”可随时暂停和恢复服务。关闭时普通用户页面隐藏消息和输入区域，服务端拒绝历史查询、消息发送、上传与附件访问；后台和管理附件仍可使用。连接保留以接收重新开启通知，在线人数表示已连接会话。关闭不删除记录，保留计时和自动清理继续运行；重新开启显示尚未过期、未被清空的消息。开关持久保存，重启不会自动开启。已经下载的内容和开始传输的附件无法撤回。首次升级需刷新聊天页面。
- 启动和每 10 分钟清理过期消息及附件，历史接口立即按可见窗口限制；页面每 30 秒移除过期消息。已经下载到他人电脑的附件无法撤回。
- 管理登录使用 Google Authenticator 的 6 位动态验证码（SHA1、30 秒，容忍前后一个时间窗口）。同一个时间步的验证码不可重复使用；绑定时用过的验证码也需要等下一组才能再次登录。电脑和手机需开启时间自动同步。
- 登录有效期 8 小时，重启服务后需要重新登录。登录、绑定与恢复共用每个来源地址每 15 分钟 10 次的限制。HTTP 未加密，管理操作建议使用部署电脑上的 localhost 页面。
- 已设置旧密码时，原密码登录在确认绑定前保持有效。在本机输入原密码后点击绑定；验证成功才清除密码并停用密码登录。重新绑定需先登录并在本机操作，新绑定确认后所有旧后台会话与旧恢复码失效。

## 数据与恢复

所有数据位于 `data/`（含 SQLite 数据库、`files/` 附件和本地加密密钥 `auth.key`）。验证器密钥使用 AES-256-GCM 加密存入数据库；恢复码只保存 SHA256 摘要。**先关闭服务**，复制整个目录作备份；恢复时停服并恢复完整目录，再启动。必须同时保留 auth.key；不要只复制运行中的 chat.sqlite，WAL 中可能有尚未合并的数据。保护整个 data 目录，本机管理员取得数据库与加密密钥后仍可读取验证器配置。

手机丢失：在部署电脑打开 localhost 后台，选择“一次性恢复码”，用任意一条未使用恢复码登录，再点击“重新绑定验证器”。每条恢复码仅能使用一次；新绑定后保存新的恢复码。不要把二维码、密钥或恢复码发到聊天中。若手机与全部恢复码均丢失，需要部署电脑持有人停服后进行本地配置恢复，无远程免验证重置接口。

## 验证

`node test.cjs` 使用独立临时数据库，覆盖旧密码迁移、错误动态码、绑定确认、动态码登录与防重放、恢复码一次性使用、密码停用和密钥加密保存，以及双会话实时消息、消息重试去重、附件权限、6 小时窗口和保留清理。`npm audit` 检查依赖。

尚需在另一台内网电脑完成访问、图片预览及文件收发验收；50 人是首版设计目标，尚无实际负载验收。固定 IP 和防火墙状态需在真实网络中确认。
