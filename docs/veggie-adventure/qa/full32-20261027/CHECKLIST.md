# 横版过关游戏全面检查清单与32关自主巡检

版本1，建立于2026-10-27。计划在**2026-10-27 06:00，Asia/Shanghai（北京时间）**开始一轮完整巡检。现在只准备清单和计划，不把准备工作记作已经完成可视化验收。

## 顺序与证据要求

1. 06:00后先读取本线程、`STATUS.md`及`progress.json`，检查Git状态和当前本地服务。保留全部已有修改。记录检查时的HEAD、工作区差异摘要、素材清单摘要和窗口尺寸，冻结为本轮基线；不覆盖其他任务的代码。
2. 按1-1、1-2…8-4顺序实际打开、观察并操作游戏。主入口为`http://127.0.0.1:3210/games/veggie-adventure/?qa=1&review=full32-audit`。`review`模式不保存旅程；不得清空或改写用户正式存档。只使用当前可用且已阅读说明的浏览器/电脑工具。
3. **逐关检查期间只记录，不修改玩法、美术或地图。** 必要的巡检工具准备与服务启动不属于玩法修复，须另记。关内遇到阻断，保留截图和复现步骤，标注未能检查的区域，继续检查其他关卡；不能因某一关有问题而跳过其余31关。
4. 每关必须有实际画面、实际输入后的观察记录。仅加载成功、入口截图、HTTP检查、无界面测试或读取对象状态，都不能替代可视化检查。可以用调试选关、形态设置与分段定位辅助补查，但必须标明，不能把直接修改坐标、血量、胜利标记或无敌状态当作真实通关。
5. 每关检查起点、路线中段、主要机关/战斗区、坑与平台、奖励、出口；对长关沿地图分段扫查，不能只看四个固定百分比就假定全图无问题。标记关键x区间及实际经过范围。1-3三条高路必须逐条进入并返回地面。
6. 基础形态进行实际路线推进；另外两种形态至少在本关所有窄口、阶梯、坑边、升降台、上下层和战斗场景进行输入验证及画面检查。区分完整战斗通关、隔离战斗的地形验证及调试定位观察。
7. 桌面横屏每关均检查。手机横屏每关至少检查HUD、场景、控件及关键战斗区域；每世界再覆盖窄横屏和竖屏，以及暂停/胜负/设置界面。建议1920×1080、844×390、568×280、390×844，并记录实际尺寸。模拟窗口不等于手机硬件验收。
8. 问题按`ISSUE_TEMPLATE.md`记录。一个共同根因建立一个主问题，列出全部受影响关卡及证据；保留逐关差异。截图先落盘再更新进度，每关完成后立即保存。
9. **所有32关都已经实看并记录结果（含阻断和覆盖缺口）后，先写`findings-summary.md`，再进入统一修改。** 按根因规划修复，优先P0/P1，再处理其他确认问题。需要新图的占位物或错误状态使用内置生图制作透明PNG，分类归档源图、提示词及运行素材。
10. 修改后执行必要回归，并用真实画面回查全部问题位置、受共用代码影响的关卡，以及初查中被阻断的区域。只有32关视觉覆盖完成、确认问题处理完成且必要检查通过，才把`complete`设为true并停止心跳。不得将“已安排”“已截图”“测试通过”写成“32关已验收”。

## 项目专门验收标准

- 初始、成长、辣椒三种形态碰撞框均12×14；成长美术比例保留。移动在约1秒起跑后达到满速；成长本身不增加跳跃能力。
- 普通移动使用奔跑动画，没有额外奔跑按键。点按跳与长按跳保留差异。
- 1-3三段高路全部可选、可破坏，可回到地面；高处敌人确实在砖层活动；全毁砖后仍有地面通路。见`LAYERED_1_3_EXPERIMENT.md`。
- 坑前后128单位（8格）内不设造成卡顶的方块或危险覆盖；区分实际深坑与可游泳池底。
- 八个Boss活动宽度432单位（原来的1.5倍）；进场短路线不被错误恢复成长图。第一世界战台为平直木梁藤蔓PNG。
- Boss保持只有弱点期才能扣血。壳兵/刺壳缩壳时踩踏双方均不扣血；昏厥飞行菜叶侧碰无伤、可继续踩至退场，9秒地面计时后醒转。
- 飞翼卷心菜使用E11自身下坠/昏厥/醒转图集；棉花云兵使用E09自身退场图，不使用E02或`objects-5`壳图。死亡表现不产生额外得分或伤害。
- 鱼、水母、水面跃出怪和水生Boss移动70%；玩家游泳及敌人弹速不随之降低；水底植物保持固定位置。
- 初始顶升级砖给胡萝卜，成长给辣椒，第三形态继续辣椒得到+1小火球、+2大火球、+3闪电球；满级只给积分。受伤/重生与跨关强化规则不能互相冲突。
- 每轮3次可重生，死亡回本小关起点，成长清零；耗尽后死亡显示结束画面，无可用检查点复活。
- 普通过关自动推进；隐藏选关房只在1-1未向右输入前，向左且滞空触左边界触发，32个选关砖按世界分组，编号仅1/2/3/4，左右可上下离开。
